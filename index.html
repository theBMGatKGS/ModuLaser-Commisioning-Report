Help — ModuLaser MASD Field Report

How to use this Field Report

The Field Report is the on-site half of a ModuLaser job. The Battery Calculator designs the system (devices, addresses, power supplies, batteries). PipeCAD designs the pipe network. This report imports both, then records what you find and test on site, and prints the commissioning report.

Quick start
1
Import the project

File → Import project… and choose the .mlproj.json saved from the Battery Calculator (02.00.001 or later). A review dialog lists every power supply, detector and display sheet that will be created or updated. Nothing changes until you press Import. Values that came from the design show a blue design tag. If you later change one, it shows an amber edited tag.

2
…or import PipeCAD directly

No calculator file yet? File → Import PipeCAD (.pl)… accepts one or more .pl files. Each Floor becomes an Area/Group; detectors, Standard/Minimum/Command displays, fan speed, Alarm Factor and the pipe and hole data are imported. Power supplies, batteries and addresses are not in a .pl, so add them from the calculator project later. The .pl PSU and Battery symbols are used for placement only. To combine several .pl files into one, use File → PipeCAD merge tool.

3
Work one sheet at a time

The left sidebar lists the report sections and every sheet, grouped Area/Group → power supply → module. Each sheet has a status dot: green PASS, red FAIL, amber INCOMPLETE. Use the search box to filter by name or address. Each device sheet has three tabs: Setup (identity, address, I/O, photos), Configure (alarm levels, fan, flow) and Test (transport time, smoke, flow faults, outputs). Use ◀ Previous / Next ▶ or Alt+↑/↓ to move between sheets.

4
Confirm typical values

Alarm levels (Alert, Action, Fire 1, Fire 2), flow limits and delays are pre-filled with typical values for the performance class (VEWFD / EWFD / SFD). They are tagged typical — confirm and keep the sheet INCOMPLETE until you either type the commissioned value or press Confirm typical values (Edit menu) after checking them on the detector.

5
Test

The pinned results panel on the right shows the sheet's result stamp, every open or failed item, the transport-time gauge (measured vs PipeCAD vs limit) and the battery gauge (installed vs required Ah). Open the Stopwatch to time transport and smoke tests; Enter writes the time straight into the selected field.

6
Save the project

Everything autosaves to this browser. File → Save project (Ctrl+S) writes the same .mlproj.json back with your site results added. The calculator's design section is kept exactly as it was, so the calculator can open the file again.

7
Print or export

File → Print / Export… (Ctrl+P) opens a live 8.5 × 11 preview. Choose a detail level (Summary, Standard, Full) and a scope (whole project, this sheet, or failed and incomplete only). Output to PDF (via the print dialog), Word (.docx), HTML or Excel (CAD Schedule + Detail).

8
Phones and tablets

Under 900 px wide, the sidebar and results panel slide in from the bottom bar. The bottom bar also has the stopwatch, camera (photo for the current sheet) and Go to device, which scans a QR label or finds a device by name or address. Installed as an app (PWA), the report works offline.

How do I…

…update the sheets when the design changes?
Re-save the project in the Battery Calculator, then File → Import project… again (or Check linked file…). The review shows a diff of what changed. Values you edited on site are kept unless you tick them. Site results are never overwritten.
…know if the linked file changed?
File → Check linked file… and pick the project or .pl file. If it differs from what was imported, a banner appears with Review & update….
…show I/O that isn't used?
Unused inputs and outputs are hidden. Press + IN1 (etc.) on the Setup tab to use one, or View → Show all I/O.
…change the allowed transport-time variance?
Section C → Settings → Measured vs PipeCAD transport, allowed over (%). Default +20%.
…switch to the light theme?
Press ◐ Light in the quick row (or View → Light / dark theme). Printing always uses the KGS print palette.
…add a photo?
Open the sheet, then 📷 (bottom bar) or Take / add photo on the Setup tab. Photos are resized to about 1024 px and are saved in the project file. Full-detail reports include them.
…jump to a device on site?
View → Go to device… (or ⌖ in the bottom bar) and scan its QR label or type its name or SenseNET address.
…move a job to another device?
Save the project and open it on the other device with Import project. The legacy Export job (.json) / Import job still work.
…build the Windows installer?
See electron/README: npm install then npm run dist in electron/.

Page numbers are the manual's own printed footer numbers, verified against the source PDF, not PDF viewer page counts.

Hole sensitivity & transport time by listing (Table 45)Table 45, p.112FM Class Number 3230 (NFPA 76 terms): VEWFD <1.00 %obs/ft, <60 s; EWFD <1.50 %obs/ft, <90 s; SFD <2.50 %obs/ft, <120 s. Also lists UL 268 Ed.7 Open Area (1.70–2.18%, 6–43 s), UL 268 Ed.7 Special Application Ranges 1/2, UL 268A Duct Ranges 1/2, and ULC-S529.
Per-hole sensitivity check (PipeCAD import)Table 45, p.112Every PipeCAD sampling hole's sensitivity is compared with the selected target's Fire 1 limit (VEWFD ≤1.0, EWFD ≤1.5, SFD ≤2.5 %obs/ft). The worst (highest) hole decides PASS/FAIL, with margin = limit − worst hole. PipeCAD's longest sampling-hole transport time is compared with the target's time limit (VEWFD 60 s, EWFD 90 s, SFD 120 s), with margin = limit − max transport. The NFPA 76 VEWFD Alert threshold (0.2 %obs/ft) is a separate alarm stage and is not applied per hole. End-cap test points are excluded.
Known discrepancies with this report's built-in defaults — flagged, not silently changed
Pre-Power-Up item 11 — EOL resistor tolerance
Section B's checklist currently reads "All input EOL resistors fitted (15 kΩ, 5%, ¼ W)?" The manual's Table 5 (p.27) specifies 15 kΩ ±10%, not 5%, and states no wattage rating for this resistor. The 5%/¼ W figures could not be confirmed against this manual and were left in the checklist text unchanged pending the document owner's decision on whether to correct the wording in a future revision.
Detector performance targets — VEWFD sensitivity
Resolved in Rev 11 (01.00.003). Up to Rev 10, the built-in VEWFD target used a 0.2 %obs/ft per-hole limit. That figure is the NFPA 76 VEWFD Alert threshold, not the Table 45 (FM Class 3230) per-hole figure. The VEWFD target now uses the Table 45 Fire 1 limit of ≤1.0 %obs/ft with the 60 s transport limit. SFD now carries Table 45's ≤2.5 %obs/ft (EWFD was already ≤1.5). A custom sensitivity limit on the sheet still overrides the target.
Detector performance targets — EN 54-20 Class A/B/C
This report's built-in EN 54-20 Class A/B/C targets currently carry no sensitivity limit and a uniform 120 s transport-time limit. The manual's own EN 54-20 compliance table (p.110) gives distinct, tighter figures per class: Class A <0.41 %obs/m & <70 s, Class B <2.221 %obs/m & <85 s, Class C <3.78 %obs/m & <95 s. This is a real gap between the report's defaults and the manual, left as-is pending the document owner's decision (changing it affects live PASS/FAIL calculations, not just reference text).

FAQ

What is the ModuLaser project file (.mlproj.json)?
One JSON file shared by the Battery Calculator and this report. The calculator owns the design section (devices, addresses, power supplies, batteries, PipeCAD links); this report owns the site section (tests, checklists, photos, sign-off). Each tool only writes its own section and shows a diff before changing anything.
Why are alarm levels pre-filled now?
From 02.00.000 the report pre-fills typical values for the performance class so technicians start from a sensible point. Fire 1 matches the Table 45 limits; the 20% flow limit is the manual default; the others are typical starting points. They are clearly tagged and the sheet stays INCOMPLETE until each is confirmed or changed on site. Always use the design or AHJ values where they differ.
Why is a 17-character name a FAIL?
The ModuLaser display shows 16 characters. Longer names are truncated on the panel, so the report fails them. The counter under the name field shows the length.
Why does battery Ah fail when the battery is fitted?
The installed Ah is compared with the required Ah from the Battery Calculator. If it is lower, the power supply fails, even if the standby test passes.
Where do addresses come from?
SenseNET addresses are set in the Battery Calculator and imported. Confirm each one on the display (Setup tab → Address confirmed on display). Duplicate SenseNET and FACU addresses fail.
What exactly does autosave cover, and what doesn't it cover?
Autosave writes the full job (project info, every module and PSU sheet, wiring segments, checklists, sign-off) to this browser's local storage about ¼ second after each change. It's scoped to one browser on one device — it does not sync between devices or browsers, and clearing that browser's site data removes it. For anything that needs to move between machines, survive a browser reset, or be archived long-term, use Export job.
What's the difference between Export/Import and Print/PDF?
Export/Import moves the underlying data (a .json job file) so work can continue on another machine or be archived and re-opened later in this same tool. Print/PDF produces a static, formatted document of the current state for signatures, submittal, or the owner's records — it can't be re-imported and edited.
Why do some configuration items have a dot (●) and others don't?
The dot marks an item that's scored toward the module's automatic PASS/FAIL/INCOMPLETE result. Un-dotted items (e.g. cascading alarms, latching behavior, Day/Night settings) are recorded for the record but don't drive the automatic result on their own — they still surface in the deficiencies list if they fail a bound (e.g. flow limits over 20%).
How does the override mechanism work, and why does it need a reason?
A device's automatic result can be overridden (e.g. a technician judges a borderline reading acceptable) only when both an override result and a non-blank reason are entered — a result with no reason is not applied, and the sheet shows a warning until one is added. This keeps every override traceable to a documented justification, both on the device sheet and in the auto-collected deficiencies list.
What triggers a SenseNET address error vs. a FACU address error?
SenseNET addresses (module/PSU network addresses) must be a whole number 1–127 and unique — out-of-range or duplicate addresses fail immediately. FACU addresses (the point label programmed at the fire alarm control unit for a given input/output/monitoring point) must match the PPP:CCC:DDDD panel/circuit/device pattern — anything else is flagged as a format error, separate from the SenseNET check.
What populates the "Outstanding items / deficiencies" list in Section G?
It's built automatically, not typed in: every "N" answer in Section B or G, every failed item on any module or PSU sheet, every wiring segment marked Fail, and every applied result override (with its reason) are collected there in one place so nothing needs to be re-transcribed by hand.
What's the difference between PASS, FAIL, and INCOMPLETE?
FAIL means at least one scored/required item failed its check. INCOMPLETE means no item has failed but at least one required item is still blank. PASS means every scored/required item passed. See "Known discrepancies" above for the EN 54-20 targets, where the built-in pass/fail limits are worth double-checking against your specific listing before relying on an automatic PASS. (The VEWFD sensitivity figure was corrected to the Table 45 Fire 1 value in Rev 11.)

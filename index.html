How to Use This Field Report

Named "How to Use This Field Report" rather than "…the Calculator" — this tool is a commissioning worksheet, not a sizing calculator, so the calculator wording was renamed to avoid confusion.

Quick Start
1
Start or resume a job

Open this file in a browser and begin — nothing to install. Every change autosaves to this browser (debounced ~¼ second) under a report-specific storage key, and the toolbar's Not saved yet / Autosaved h:mm status confirms it. If the browser can't store data (private/incognito mode, storage disabled, or storage full), the status instead reads Autosave unavailable — use Export job — save your work with Export job in that case. To hand a job to another technician, move it to another computer, or keep an archival copy, use Export job (downloads a .json job file) and Import job (loads one back in). New job clears the current browser data after a confirmation prompt — export first if you want to keep it. The toolbar's Revision and Date cells show which build you are running; Help → Revision Log lists every change since the Rev 10 baseline, plus the reconstructed legacy history.

1b
Optional — Import PipeCAD (.pl)

Use Import PipeCAD (.pl) to pre-fill the report from a PipeCAD 3.6 project export. The file is read in this browser only. A preview lists every Section A field and detector sheet that would be set, replaced, or kept, with each detector's design check against its performance target. Nothing changes until you confirm. Section A gets the site (ProjectName), system designer, a "PipeCAD location" line in Notes, the installing company (only if blank), and the file name + PipeCAD version as the report reference. Each PipeCAD detector becomes one detector sheet, or updates the sheet whose descriptor matches its name. The sheet gets its descriptor, fan speed, Alarm Factor, PipeCAD transport time, sampling-hole count, the performance target (only if blank, from PipeCAD's max transit time) and a PipeCAD design data block: pipe, pipe length (sum of the 3D pipe segments), total flow, hole balance, fittings, design sensitivity, and the full hole table. If the Alarm Factor isn't activated in PipeCAD, the sheet flags it for verification. End-cap test points are listed separately and excluded from the worst-hole and max-transport checks. Not imported: SenseNET address, part number, Alert/Action/Fire 1/Fire 2 levels and flow limits — enter those from the field. Re-importing an updated .pl keeps everything entered in the field. Several .pl files (for example one per floor) can be selected together: they are merged into one project, the preview lists any renamed floors or detectors and renumbered IDs, and Download merged .pl saves the combined file. All files must use the same units. JSON Export/Import, autosave and print are unaffected.

2
Section A — Project Information

Record the site, job number, address, commissioning date, installing company, commissioning engineer, system designer, owner contact, PipeCAD report reference, FACU make/model, and SLC panel count. This block also drives the header/footer text shown on every printed page.

3
Section B — Pre-Power-Up Inspection

Work the 17-item checklist before applying power: FACU isolation, PipeCAD pipe-length limits, pressure zone and exhaust placement, sampling-hole count and condition, cable knockouts, field wiring including SenseNET/SNET+ data lines, EOL resistors and EOL PCBs, supply voltage, battery standby capacity, FACU SLC addressing, clearance, housekeeping, and ESD precautions. Each row is Y / N / N/A with a notes field. The section header shows a live rollup (Y/N/N-A/open counts and a PASS/FAIL/INCOMPLETE badge) — any "N" answer here also appears automatically in Section G's deficiencies list.

4
Section C — Module & Power Supply Index

Add every detector module, standard display module, command display module, and "other" module with the four buttons at the top — each becomes its own sheet in Section D. Add power supplies with the button below the module index — each becomes its own sheet in Section E. Addresses/order are kept sorted automatically by SenseNET address. This section also holds the Test setup block shared by every detector's tests: test method (smoke pen, hot-wire, smoke pellet, listed canned smoke, other), material used, release location, whether Demo Mode was used, and equipment/calibration notes.

5
Section D — Module Sheets

Each module gets its own sheet with four blocks: 1 Identity & location (SenseNET address 1–127, type, model, serial, firmware, cluster/group, location/zone), 2 Inputs & outputs (mark each of IN1/IN2/OUT1/OUT2/OUT3 used or not, with its FACU address in PPP:CCC:DDDD format and function — display modules have OUT1 fixed to General Fault), 3 Configuration (alarm levels, fan speed, flow limits, and the other designer-sourced values — no defaults are assumed for a detector's alarm/fan/flow settings), and 4 Tests (an input/output test verified at the FACU). Configuration items marked with a small dot (●) and every populated required field count toward the module's automatic PASS/FAIL/INCOMPLETE result, shown at the top-right of the sheet and rolled up per section along the bottom. Detector modules get a second page with hole-sensitivity/performance targets and three additional tests (transport time, smoke detection, airflow fault). If a result needs to be overridden, enter both an override result and a reason at the bottom of the sheet — an override with no reason is not applied and is flagged with a warning.

6
Section E — Power Supply Sheets

Each power supply gets identity/circuit/battery fields, the two FACU monitoring points (AC fail and general trouble, each with a PPP:CCC:DDDD address), and a battery/power test (voltage with AC on/off, standby hours measured against the design requirement, and mains/battery/FACU fault verification). The same override-with-reason mechanism applies here.

7
Section F — SenseNET / SNET+ Wiring Verification

Add one row per wiring segment (node to node): bus type, topology, cable type/gauge, length, EOL fitted, continuity and isolation readings, and total measured capacitance (auto-calculated from capacitance-per-foot × length). Mark each segment Pass/Fail — a Fail here feeds directly into Section G's deficiencies list.

8
Section G — Final Commissioning Checklist

Work the 22-item final checklist (addressing, date/time, access codes, alarm factors and levels, airflow fault limits, wiring, pipe network, transport time, smoke tests, output/flow/power-fault verification at the FACU, Demo Mode and final FastLearn, housekeeping, baseline, training, and handover) the same Y/N/N-A way as Section B. Below it, Outstanding items / deficiencies is built automatically — it collects every "N" from Sections B and G, every failed item on every module and power supply sheet, every failed wiring segment, and any applied result override, so you don't have to re-transcribe them. A free-text field is available for anything else outstanding.

9
Section H — Module Test Summary

A read-only rollup: tiles for devices tested / pass / fail / incomplete, then a per-module table (one column per test group — network, I/O, configuration, sensitivity, transport time, smoke, airflow, outputs, inputs), a per-power-supply table, and a system-level table for pre-power inspection, wiring, and the final checklist. An asterisk marks a device whose result was manually overridden, with the override reason listed below the tables.

10
Section I — System Acceptance & Sign-Off

Review the live test-summary line, set the overall acceptance status (System Accepted / Not Accepted / Accepted with Conditions), add acceptance comments if needed, and complete the three signature blocks — installing technician, commissioning engineer, and owner's representative — each with its own attestation statement.

11
Print or export the finished report

Print / PDF opens the browser print dialog against a plain Portrait Letter page with running headers/footers (document + revision, site/job/date, and Page X of Y) — every input becomes a printed value first, so nothing is lost from view. Use Export job afterward (or before) to keep a .json archive of the underlying data, separate from the printed/PDF copy.

Worked Example

A single sample cluster, start to finish, with example values only — substitute your own PipeCAD design and field readings.

A
Project Information

Site "Acme Data Center — Level 3", Job 24-0158, commissioning date entered, FACU "Edwards EST4", PipeCAD report "PC-24-0158 Rev B" recorded in Section A.

B
Pre-power-up

Pipe run measured at 210 m combined with 2 t-pieces — within the 250 m / 820 ft combined limit — marked Y; EOL resistors and EOL PCBs confirmed fitted, marked Y; supply voltage measured 24.1 VDC, within 21.2–27.2 VDC, marked Y.

C/D
Add and configure a detector module

Add a detector module at SenseNET address 012, descriptor "AHU-3 Return", location "Mech Room 3B". Mark IN1 used with FACU address 001:002:0012, function "Isolate"; OUT1 used with function "General Fault". In Configuration: Alarm Factor 4, Alert 0.5, Action 1.0, Fire 1 1.5, Fire 2 3.0, Fan speed 8, Flow low limit 15%, Flow high limit 18% (both within the ≤20% limit). Performance target set to NFPA 76 — EWFD (≤1.5 %obs/ft · ≤90 s). Chamber sensitivity at Fire 1 read 0.6 %obs/ft across 3 sampling holes → average hole sensitivity 1.8 %obs/ft, which the sheet flags as exceeding the 1.5 %obs/ft EWFD limit — a real discrepancy the technician would need to resolve (re-check PipeCAD hole sizing) before the module can PASS.

D2
Transport time and smoke test

PipeCAD-predicted transport time 42 s; measured 46 s (a +9.5% variance, within the informal 20% variance flag). Three smoke-pen runs at 44 s, 46 s, 45 s (all ≤ the 90 s EWFD limit — Pass), first alarm reached at Action, verified at the FACU.

E
Power supply

PSU "PSU-2", 7 Ah battery, required standby 24 hrs. Battery V with AC on: 27.4 V; AC off: 26.1 V; standby measured 26 hrs (meets the 24 hr requirement) — Pass.

F
Wiring segment

SN 010 → SN 012, SenseNET+, closed loop, 16 AWG shielded twisted-pair, 38 ft, EOL fitted, continuity/isolation/capacitance all within normal range — Pass.

G–I
Final checklist and sign-off

Because the hole-sensitivity discrepancy above wasn't yet resolved, this module shows FAIL and appears in Section G's deficiencies list automatically ("SN 012 — Detector — Hole sensitivity: 1.800 %obs/ft exceeds 1.5 limit"). The technician either corrects the pipe design/hole count and re-tests, or enters an override result with a documented reason once the discrepancy is otherwise resolved. Once every device and checklist item is clean, Section I shows the test-summary line, the acceptance status is set to System Accepted, and all three parties sign.

Known discrepancies with this report's built-in defaults — flagged, not silently changed
Pre-Power-Up item 11 — EOL resistor tolerance
Section B's checklist currently reads "All input EOL resistors fitted (15 kΩ, 5%, ¼ W)?" The manual's Table 5 (p.27) specifies 15 kΩ ±10%, not 5%, and states no wattage rating for this resistor. The 5%/¼ W figures could not be confirmed against this manual and were left in the checklist text unchanged pending the document owner's decision on whether to correct the wording in a future revision.
Detector performance targets — VEWFD sensitivity
Resolved in Rev 11 (01.00.003). Up to Rev 10, the built-in VEWFD target used a 0.2 %obs/ft per-hole limit. That figure is the NFPA 76 VEWFD Alert threshold, not the Table 45 (FM Class 3230) per-hole figure. The VEWFD target now uses the Table 45 Fire 1 limit of ≤1.0 %obs/ft with the 60 s transport limit. SFD now carries Table 45's ≤2.5 %obs/ft (EWFD was already ≤1.5). A custom sensitivity limit on the sheet still overrides the target.
Detector performance targets — EN 54-20 Class A/B/C
This report's built-in EN 54-20 Class A/B/C targets currently carry no sensitivity limit and a uniform 120 s transport-time limit. The manual's own EN 54-20 compliance table (p.110) gives distinct, tighter figures per class: Class A <0.41 %obs/m & <70 s, Class B <2.221 %obs/m & <85 s, Class C <3.78 %obs/m & <95 s. This is a real gap between the report's defaults and the manual, left as-is pending the document owner's decision (changing it affects live PASS/FAIL calculations, not just reference text).

FAQs

What exactly does autosave cover, and what doesn't it cover?
Autosave writes the full job (project info, every module and PSU sheet, wiring segments, checklists, sign-off) to this browser's local storage about ¼ second after each change. It's scoped to one browser on one device — it does not sync between devices or browsers, and clearing that browser's site data removes it. For anything that needs to move between machines, survive a browser reset, or be archived long-term, use Export job.
What's the difference between Export/Import and Print/PDF?
Export/Import moves the underlying data (a .json job file) so work can continue on another machine or be archived and re-opened later in this same tool. Print/PDF produces a static, formatted document of the current state for signatures, submittal, or the owner's records — it can't be re-imported and edited.
Why do some configuration items have a dot (●) and others don't?
The dot marks an item that's scored toward the module's automatic PASS/FAIL/INCOMPLETE result. Un-dotted items (e.g. cascading alarms, latching behavior, Day/Night settings) are recorded for the record but don't drive the automatic result on their own — they still surface in the deficiencies list if they fail a bound (e.g. flow limits over 20%).
Why are alarm levels, fan speed, and flow limits left blank with no defaults?
Those values are set by the PipeCAD design for the specific pipe network and application, not by this tool — entering a default here could mask a design value never having been transcribed. The Configuration block explicitly requires them to be entered from the designer's documentation.
How does the override mechanism work, and why does it need a reason?
A device's automatic result can be overridden (e.g. a technician judges a borderline reading acceptable) only when both an override result and a non-blank reason are entered — a result with no reason is not applied, and the sheet shows a warning until one is added. This keeps every override traceable to a documented justification, both on the device sheet and in the auto-collected deficiencies list.
What triggers a SenseNET address error vs. a FACU address error?
SenseNET addresses (module/PSU network addresses) must be a whole number 1–127 and unique — out-of-range or duplicate addresses fail immediately. FACU addresses (the point label programmed at the fire alarm control unit for a given input/output/monitoring point) must match the PPP:CCC:DDDD panel/circuit/device pattern — anything else is flagged as a format error, separate from the SenseNET check.
What populates the "Outstanding items / deficiencies" list in Section G?
It's built automatically, not typed in: every "N" answer in Section B or G, every failed item on any module or PSU sheet, every wiring segment marked Fail, and every applied result override (with its reason) are collected there in one place so nothing needs to be re-transcribed by hand.
What's the difference between PASS, FAIL, and INCOMPLETE?
FAIL means at least one scored/required item failed its check. INCOMPLETE means no item has failed but at least one required item is still blank. PASS means every scored/required item passed. See "Known discrepancies" above for the EN 54-20 targets, where the built-in pass/fail limits are worth double-checking against your specific listing before relying on an automatic PASS.

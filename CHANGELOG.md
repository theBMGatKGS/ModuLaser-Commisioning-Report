# Changelog

All notable changes to the Edwards ModuLaser MASD Field Report are documented here.

Format: `MM.mm.rrr` (major.minor.revision), date `YYYY-MM-DD`. Major and minor
versions are set manually by the document owner; the revision counter increments by
one per distinct logical change and resets when the minor/major version changes.
This file is generated from the app's own in-app log (Help → Revision Log) — that
log (`AMENDMENTS` / `LEGACY` in `index.html`) is the source of truth; regenerate
this file from it rather than hand-editing both. Per-release summaries are in
[RELEASE_NOTES.md](RELEASE_NOTES.md).

## 02.01 — 2026-10-16

### 02.01.000 — 2026-10-16 (released 2026-10-17; QA/Auditor GO on b7cbadb)
- **MiniLaser ASD (FHSD8075-ULF) (Brent 2026-10-16).** New module type, standalone and never addressed (SenseNET checks don't apply). It comes in from the Battery Calculator 02.01.000 / Toolbox 00.02.000 project file, from a PipeCAD .pl (SOLO detectors), or via **+ MiniLaser**.
- **MiniLaser class from a .pl (Brent-approved):** area override → project standard → SFD (max transport time no longer used). A MiniLaser from a .pl is non-pre-engineered by default (Brent); DIP/Remote advice follows the fan 2/4/7/10 + AF 2/4/6/8 rule; `modulaser-project.js` 1.5.1 (was 1.5.0) (identical in all three apps). A 40 % flow-fault level shows PASS with a warning note (Brent-approved).
- **QA delta (02.01.000 review).** F1: a new "Holes / pipe length (M p.66)" check fails a MiniLaser with more holes than its application allows (e.g. 20 holes on a VEWFD application, where the max is 10) or a longer pipe than allowed. F5: the 40% flow-fault note reads "UL/FM requires ≤20% (M p.71)" (still a PASS row with a warning). Tests: `minilaser_report_test.py` uses the fixture `/workspace/qa/minilaser/hoistway.mlproj.json` (no /tmp leftovers) and writes everything under `$MLP_TEST_OUT`.
- **Final (QA GO + Brent).** `modulaser-project.js` **1.5.1** (adds the M p.66 pipe limits). `tests/minilaser_report_test.py` skips gracefully, with a clear message, when Brent's Example Shaft fixtures (kept off GitHub) are absent.
- **Release prep (QA delta 3).** `minilaser_report_test.py` always runs the fixture-free pipe-limit and 40% flow checks, then skips the Example Shaft section with `SKIPPED` in its summary when the fixtures are absent (exits non-zero with `REQUIRE_FIXTURES=1`). README now says MLP 1.5.1.
- **Setup:** R1 Fault relay (fixed, fail-safe), R2 Relay output 1 (Prealarm), R3 Relay output 2 (Fire Alarm), IN1 (15 kΩ supervised). Each I/O Expansion Module (9-30521, 0–2) adds X1/X2 OUT1–5 (latched relays, 2 A @ 30 VDC) and IN1–2.
- **Configure:** fan speed and Alarm Factor come from the design. Application (Table 35), configuration method, alarm delay and flow-fault level/delay start blank, with no numeric prefills. A blank fan speed shows INCOMPLETE ⚠ in amber.
- **Checks:** hole sensitivity (Fire 1 for the alarm factor × holes) and measured transport time are checked against Table 35 for the selected application. A 40% flow fault on a UL/FM application is a warning only. Tests cover transport, smoke, airflow fault and relays/inputs. Print/Word/Excel exports include the MiniLaser sheet.
- `modulaser-project.js` 1.5.1. New test: `tests/minilaser_report_test.py` (20), which includes the pl-merge round trip.

## Release tagging

`_YYMMDD` date suffix appears in-app only). "Rev 11" is the field name for
01.00.002–01.00.003, released as **v01.00.003**; **v01.00.004** adds this
revision archive. Revisions 01.00.000–01.00.001 predate tagging.
